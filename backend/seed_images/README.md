# seed_images — جعبهٔ عکسها

اینجا عکسهای واقعی محصولها و مقالهها را میگذارید و با یک فرمان، به کاتالوگ و ویکی
وصلشان میکنید. عکسها **commit نمیشوند** (فقط همین README و پوشه میمانند).

## روال کار

۱. اگر جای خالی هست، اسکلت را بسازید — برای هر جای خالی یک تصویر پلیسهولدر با نام درست:

   ```powershell
   cd backend
   ..\.venv\Scripts\python.exe manage.py placeholder_images
   ```

۲. فایلهای `*.png` را با عکس واقعیِ **همنام** جایگزین کنید (پسوند jpg / png / webp).

۳. پیوست کنید (اول پیشنمایش، بعد واقعی):

   ```powershell
   ..\.venv\Scripts\python.exe manage.py import_images --dry-run
   ..\.venv\Scripts\python.exe manage.py import_images --force
   ```

`--force` عکس قبلی (پلیسهولدر) را با عکس واقعی عوض میکند. فهرست نامهایی که هنوز
باید پر شوند:

```powershell
..\.venv\Scripts\python.exe manage.py image_audit --names
```

از پنل مدیریت (`/admin-panel`) هم میشود عکس گذاشت؛ این پوشه برای کار دستهای است.

## نام فایل (حساس به بزرگی/کوچکی حرف نیست)

| نام فایل | به چه چیزی وصل میشود |
|---|---|
| `entity-<slug>.png` مثل `entity-rtx-4070-super.png` | محصول(های) آن قطعه **و** مقالهٔ ویکیاش |
| `product-<sku>.png` مثل `product-tb-gpu-4060.png` | همان محصول |
| `page-<slug>.png` مثل `page-psu-sizing.png` | همان صفحهٔ ویکی |

پیشوند صریح (`entity-`, `product-`, `page-`) دقیقاً تعیین میکند فایل به چه چیزی وصل
شود، پس هیچ ابهامی نیست. بدون پیشوند هم کار میکند (اول SKU، بعد قطعه، بعد صفحه).

## قواعد فایل

- قالب: **JPEG، PNG یا WebP** (SVG پذیرفته نمیشود).
- حجم: **حداکثر ۵ مگابایت**.
- محتوا با Pillow بررسی میشود؛ فایلی که فقط پسوندش عوض شده باشد رد میشود.

`import_images` هیچوقت عکس یک مدل را روی مدل دیگر نمیگذارد: نامی که به هیچ محصول،
قطعه یا صفحهای نخورد، فقط **گزارش** میشود.
