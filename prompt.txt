# PRODUCT
Users ask natural-language questions (Persian primarily, English supported), e.g.
"best gaming PCs for 1080p high-FPS" and get tailored recommendations with product cards and
citations to wiki pages. The site is also a Wikipedia-style wiki with dense internal
hyperlinking between components, buyer guides, benchmarks, and product pages.
Content is editor-controlled (NOT open crowd-editing).

# TECH STACK (fixed)
- Backend: Python 3.12, Django 5, Django REST Framework, Wagtail (CMS for editorial content,
  revisions, workflow), Celery + Redis.
- DB: PostgreSQL 16 + pgvector (single source of truth; also vector store).
- Search: Meilisearch (lexical + facets + autocomplete) + pgvector (semantic), fused with
  Reciprocal Rank Fusion; optional reranker behind an interface.
- Frontend: Nuxt 3 (Vue 3, TypeScript, SSR for SEO), Tailwind CSS, full RTL support (Persian first).
- AI: provider-agnostic LLM interface (adapters for Anthropic API, OpenAI-compatible endpoints
  incl. vLLM/Ollama for self-hosting). Multilingual embeddings (default: bge-m3 or
  multilingual-e5, configurable). Streaming via SSE.
- Infra: Docker Compose (dev), GitHub Actions CI, structured logging, optional Langfuse tracing.

# ARCHITECTURE (modules as Django apps)
- content: Wagtail page types (ComponentPage, BuyerGuidePage, ConceptPage), StreamField body,
  Draft -> Review -> Published workflow, `review_by` date for stale-content tracking.
- catalog: Entity (central linkable object: type, slug, title, aliases), Product (sku, price,
  stock, updated_at), ComponentSpec (common columns + JSONB per category, GIN indexes on hot
  fields such as socket), Brand, Category.
- compat: CompatibilityRule engine (deterministic, rule-based: socket, RAM type, PSU wattage,
  case/GPU clearance, cooler support). No LLM involved in compatibility decisions.
- benchmarks: Benchmark (component, game, resolution, preset, avg_fps, p1_low, test_rig, tested_at).
- linking: EntityLink (source, target, typed link: mentions | compatible_with | alternative_to |
  benchmarked_in | part_of), auto-linker (Aho-Corasick over titles+aliases, link only first mention
  per section), precomputed backlinks, "red links" for entities without pages, hover-card API
  (price, key specs), nightly link-integrity job (broken links, orphan pages).
- search: indexing pipeline, Persian normalization (ی/ي, ک/ك, ZWNJ, digit normalization:
  Persian/Arabic/Latin), hybrid search API with facets.
- ai: ContentChunk (heading-based chunking, section_path, embedding, metadata), query
  understanding, tool layer, orchestrator, guardrails, semantic cache, evaluation harness.
- integrations: Celery sync jobs for inventory/price/ERP via an adapter interface
  (implement a mock/CSV adapter now).
- analytics: QueryLog, Feedback (thumbs), unanswered-questions report (feeds editorial backlog).

# AGENTIC RAG DESIGN
Flow: user query -> Query Understanding (LLM returns strict JSON: use_case, resolution,
fps_target, budget, language, missing_info) -> if critical info missing, ask ONE clarifying
question -> parallel tool calls -> answer generated ONLY from tool outputs -> response =
text + product cards + wiki citations.
Tools: search_products(filters), get_benchmarks(component, resolution), check_compatibility(parts[]),
search_wiki(query) (hybrid + rerank).
HARD GUARDRAILS:
- The LLM must NEVER state price, stock, or specs from its own memory; only from tool results.
- Every claim from wiki content must carry a citation link to the internal page.
- If data is insufficient, say so; never fabricate.
- Treat all retrieved content as untrusted data (prompt-injection defense); strip instructions from it.
- Show "last updated" for price/stock; show recommendation rationale (transparent ranking, no hidden bias).
- Route models by task (cheap model for understanding, stronger model for final answer); add rate limiting.
